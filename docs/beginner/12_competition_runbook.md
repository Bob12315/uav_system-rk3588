# 12：比赛当天操作清单

## 本章目标

把比赛准备变成固定、可复核的流程，避免因紧张跳过配置、场地或安全检查。建议打印本章，
由操作员和复核员共同签字。

## 角色

至少明确：

- 飞手：负责遥控器和最终接管；
- Web 操作员：负责场地初始化和 Mission；
- 硬件负责人：负责电池、接线、投放机构；
- 观察员/安全员：负责场地净空和喊停；
- 复核员：逐项检查配置、参数和清单。

人数不足时可以一人兼任，但飞手不应在关键飞行阶段同时低头操作网页。

## A. 到场前

- [ ] 代码 commit、模型、实机 profile 和 Mission 模板已冻结并记录。
- [ ] `python scripts/validate_action_missions.py` 通过。
- [ ] 关键测试、SITL 和无载荷实飞记录完整。
- [ ] 飞控参数、RK3588 配置和日志已备份。
- [ ] 电池、备用桨、线材、工具、模拟载荷和网络设备齐全。
- [ ] 没有未提交且来源不明的板端改动。

## B. 整机检查

- [ ] 机架、电机、桨、紧固件和重心检查完成。
- [ ] RK3588、飞控、GPS、相机和投放机构固定可靠。
- [ ] 电池、DC-DC、连接器无损伤或过热痕迹。
- [ ] 两个 payload 编号和对应 SERVO 输出明确。
- [ ] 遥控器、地面站和 failsafe 已检查。
- [ ] 安全区和人员分工明确。

## C. 上电后只观察

- [ ] `executor.send_commands: false`。
- [ ] app/yolo 服务稳定，无反复重启。
- [ ] Web UI、视频流、YOLO 检测正常。
- [ ] telemetry heartbeat、GPS、姿态、高度正常。
- [ ] 电压、温度、网络和存储正常。
- [ ] 当前 Mission 是经批准的 `rescue_2026_full_auto_v2` 或指定分项。

## D. Field Reference

- [ ] 飞机位于正式起飞点并保持静止。
- [ ] forward marker GPS 由两人复核。
- [ ] 采样数量、质量、离散度和 baseline 合格。
- [ ] 地图中前向、投放区、侦察区与真实场地一致。
- [ ] confirmed、synced、frozen 均为 true。

## E. Mission 复核

- [ ] 起飞高度、阶段速度和返航高度符合当天方案。
- [ ] 投放区、侦察区、返航点和视觉降落目标正确。
- [ ] 两个 payload、SERVO 输出和 PWM 与空载验证记录一致。
- [ ] 失败重试和 jump_to 不会重复投放。
- [ ] 侦察/视觉失败后仍有安全返航和 LAND 路径。
- [ ] blackbox 和必要录像已准备。

## F. 开启自动动作前

- [ ] 飞手、操作员、观察员和复核员全部口头确认。
- [ ] 场地净空，天气和 GPS 条件允许。
- [ ] 遥控器接管模式明确。
- [ ] 系统 SEND 和 Action send_actions 将由指定操作员开启。
- [ ] 任何人喊停都立即终止自动任务并由飞手接管。

## G. 任务后

- [ ] 先关闭 SEND，再停止/重置 Mission。
- [ ] 飞机断电后再处理载荷和接线。
- [ ] 保存 app、yolo、blackbox、飞控和录像数据。
- [ ] 记录任务结果、异常、人工接管和配置版本。
- [ ] 未复盘前不临时修改多个参数后再次起飞。

故障时转到 [故障排查](13_troubleshooting.md)。
